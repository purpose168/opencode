配置 Windsurf 的 Cascade AI 助手，以帮助您编写和维护文档。本指南展示如何专门为您的 Mintlify 文档工作流程设置 Windsurf。

## 前提条件

- 已安装 Windsurf 编辑器
- 可访问您的文档仓库

## 工作区规则

创建工作区规则，为 Windsurf 提供有关您的文档项目和标准的上下文信息。

在项目根目录创建 `.windsurf/rules.md` 文件：

````markdown
# Mintlify 技术写作规则

## 项目背景

- 这是一个在 Mintlify 平台上的文档项目
- 我们使用带有 YAML 前置元数据的 MDX 文件
- 导航在 `docs.json` 中配置
- 我们遵循技术写作最佳实践

## 写作标准

- 指令使用第二人称（"您"）
- 使用主动语态和现在时
- 流程开始处列出前提条件
- 为主要步骤包含预期结果
- 使用描述性、富含关键词的标题
- 保持句子简洁但内容丰富

## 必需的页面结构

每个页面必须以前置元数据开始：

```yaml
---
title: "清晰、具体的标题"
description: "用于 SEO 和导航的简明描述"
---
```

## Mintlify 组件

### 提示组件

- `<Note>` 用于有用的补充信息
- `<Warning>` 用于重要警告和破坏性变更
- `<Tip>` 用于最佳实践和专家建议
- `<Info>` 用于中性上下文信息
- `<Check>` 用于成功确认

### 代码示例

- 在适当情况下，包含完整、可运行的示例
- 使用 `<CodeGroup>` 用于多种语言示例
- 所有代码块都添加语言标签
- 包含真实数据，而非占位符
- API 文档使用 `<RequestExample>` 和 `<ResponseExample>`

### 流程

- 使用 `<Steps>` 组件用于顺序指令
- 相关时，包含带有 `<Check>` 组件的验证步骤
- 将复杂流程分解为更小的步骤

### 内容组织

- 使用 `<Tabs>` 用于平台特定内容
- 使用 `<Accordion>` 用于渐进式披露
- 使用 `<Card>` 和 `<CardGroup>` 用于突出显示内容
- 将图像包装在带有描述性替代文本的 `<Frame>` 组件中

## API 文档要求

- 使用 `<ParamField>` 记录所有参数
- 使用 `<ResponseField>` 显示响应结构
- 包含成功和错误示例
- 使用 `<Expandable>` 用于嵌套对象属性
- 始终包含身份验证示例

## 质量标准

- 发布前测试所有代码示例
- 内部链接使用相对路径
- 为所有图像包含替代文本
- 确保正确的标题层次结构（从 h2 开始）
- 检查现有模式以保持一致性
````
